twr_

One conversation for all your coding agents.

You talk to one orchestrator. It starts and messages Claude Code, Codex, Grok Build or any Agent Client Protocol agent, each in its own git worktree. When a thread finishes, asks a question or wants a permission, it comes back to that same conversation, summed up in a sentence or two.

curl -fsSL https://twr.tools/install.sh | sh

Linux and macOS, x86_64 and arm64.

No sidebar of chats

Most multi-agent tools give you a list of sessions to click through, and each agent waits in its own tab until you notice it. In twr you stay in one place. Say what you want and the orchestrator routes it.

on api, add a health check and push it

Started api on Claude Code, in its own worktree on branch twr/api.

· hub update

api wants to run git push origin twr/api. Allow it?

allow api

Allowed. api is pushing.

· hub update

api is done. It added GET /healthz with a test and pushed twr/api.

Press Enter twice on a card when you want that agent's full transcript, and Esc to come back. You never have to.

It relays, it never decides

The orchestrator can pass on an answer you gave. It can't make one up. A short command such as "allow both" or "deny the webapp one" applies at once. Anything longer goes on a card that only you can confirm, and every answer names the exact version of the question you saw.

Also

  • One Rust binary. No account, no cloud service, no telemetry.
  • Move the orchestrator to another agent mid-conversation. The new one starts from a handoff summary.
  • Park a thread to free its worktree, and resume it later on the same session.
  • twr attach opens the agent's own CLI on the thread's session.
  • Threads can run on other machines through twr runner.
